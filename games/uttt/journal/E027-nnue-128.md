Step D3 of [the roadmap](../ROADMAP.md#d-scale), its next idea after [E026](E026-fused-children.md): a narrower network, for speed. The owner agreed to the fit-only run and its test on 2026-10-16 ("2. I agree").

**The fit** ([run 38876178171](../training/runs/38876178171/report.md)) is fit-only on E024's data (run 38799715918, the same split and copies dropped), with `uttt-v016`'s settings: 8 epochs, target result, 14 minutes. Compared with `uttt-v016`'s network on the same held-out positions:

| | This network (128) | `uttt-v016`'s (256) |
| --- | --- | --- |
| Squared error, all 4.8M held-out positions | 0.0695 | 0.0652 |
| Cross-entropy, nats | 0.6282 | 0.6176 |
| Move agreement, 49,860 positions spread evenly | 39.7% | 45.9% |
| Move agreement, plies 8 to 31 | 33.7% to 41.0% | 43.7% to 48.1% |
| Calibration gap | 0.0079 | 0.0110 |
| Dead first-layer units | 0 of 128 | 0 of 256 |
| Packed size | 13,696 characters | 27,264 characters |

Halving the width cost more than doubling it gained ([E025](E025-nnue-512-side-games.md): 0.0646 and 46.0%). The loss is mostly in choosing the search's move, the measure that has tracked strength (E023).

**Screening against `uttt-v016`** at CodinGame's limits (Claude's 4-core session, both bots compiled with Rust 1.90.0, 4-ply openings, seed 1, 3 games at a time, 100 pairs): 30 wins, 61 draws, 109 losses, -145.1 Elo [-186.8, -107.0]. Each bot had 1 timeout; 99.9% of answers came within 97.9 ms for the candidate and 97.1 ms for `uttt-v016`. In one pair of games watched beforehand, the candidate ran about 1.8 times as many iterations per turn (about 48,000 against 26,000 on average). With the network, the bundle took 56,900 characters (`Network<128>` and `Mcts<NnueBoard<128>>` in the bot's `main.rs`).

**Decision.** Dropped without an SPRT, as the experiment checklist says for a candidate clearly weaker in screening: the whole 95% interval lies beyond -100 Elo.

**What follows.** Speed does not buy back judgment at this scale: 1.8 times the iterations did not make up for 6 points of move agreement. Together with E019 and E025, the width of 256 stands on both sides, so evaluation speed (step D3) must come from the same network computed faster (checkpoints for the walk's updates), not a smaller one; and strength from data, as E024 showed. The bot change is in this pull request's first commit, and the network stays on the run's branch `claude/train/38876178171` until it is pruned.
